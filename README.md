# 机房资产盘点系统

基于 **FastAPI + Vue3 + Element Plus + 微信小程序** 的机房资产盘点系统。

管理员在PC后台上传待盘点清单、指派任务、查看盘点结果；
现场人员通过微信小程序扫码盘点。

当前 Mac / Windows 脚本的逐项用途、调用关系及 `.env` 查找方式见[脚本使用说明](SCRIPT_GUIDE.md)；哪些文件必须保留、哪些可清理，见[项目文件保留与清理说明](docs/项目文件保留与清理说明.md)。 给其他人开通后台访问，见[协作管理员后台访问开通指引](docs/协作管理员后台访问开通指引.md)。

## 快速开始

### macOS 开发环境

从 Windows 迁移后，先确认原系统的 `.env` 和 `data/inventory.db`
已经放入项目对应位置。Mac 操作脚本位于 `scripts/mac/`，Windows 脚本位于 `scripts/windows/`。之后可在访达中双击 `scripts/mac/start_all_mac.command`，
脚本会在首次运行时自动初始化环境，并一键启动后端、Vue 管理端和
本地 AI Agent。管理端就绪后会自动打开浏览器。

运行期间请保留终端窗口，按 `Control-C` 可停止本次脚本新启动的服务；复用的已有服务不会停止。
也可以在终端运行：

```bash
cd ~/equipment_inventory
./scripts/mac/start_all_mac.command
```

如需分别启动各项服务，可先初始化环境：

```bash
cd ~/equipment_inventory
./scripts/mac/setup_mac.sh
```

分别在终端中启动后端、Vue 管理端和可选的本地 AI Agent：

```bash
./scripts/mac/start_backend_mac.sh
./scripts/mac/start_admin_mac.sh
./scripts/mac/start_agent_mac.sh
```

后端健康检查地址为 http://127.0.0.1:8000/health，Vue 管理端地址为
http://127.0.0.1:5173，本地 AI Agent 地址为 http://127.0.0.1:9000/health。

#### 小程序模式切换

在访达中双击 `scripts/mac/switch_mode_mac.command`，在弹窗中选择模式并点击“切换”：

```text
1. 线上调测：测试人员账号 + 本机接口，不使用内网穿透
2. 线下测试：真实微信账号 + 公网接口，使用内网穿透
```

脚本会自动切换 Cloudflare Tunnel、同步小程序和后端配置、重启后端并检查接口。
需要系统权限时，会弹出 Mac 授权框；输入的是 Mac 管理员密码，不是在终端中输入。
已运行的公网连接会复用，无需反复授权。公网连接检查最多等待约 30 秒，终端会显示进度。
成功后弹窗提示结果；授权取消不会修改配置，后端或公网检查失败会恢复原配置和连接状态。
若系统服务恢复也失败，会保留仅本机可访问的临时配置备份，并明确显示位置。

切换完成后，请在微信开发者工具中重新编译，并退出原账号后按所选模式重新登录。
手机上的体验版需要重新上传，脚本不会自动发布小程序。

也可以在终端直接指定模式：

```bash
./scripts/mac/switch_mode_mac.command online
./scripts/mac/switch_mode_mac.command field
```

## Vue PC后台使用说明

账号管理现支持「完整管理员」和「协作管理员」的独立账号与密码。协作管理员可查看全部机房、执行人工比对和修正资料；不能管理账号、作废任务或修改系统配置。异地登录还需要单独开通受保护的 HTTPS 后台入口，具体步骤见[协作管理员与异地访问](docs/协作管理员与异地访问.md)。

远程后台页面和服务端 Access 验证已实现，使用专用域名及同源 `/api`，默认关闭。双击 `scripts/mac/prepare_remote_admin_mac.command` 可准备正式页面和自检；仍需配置 Cloudflare Access 的团队域名、应用 AUD、获准邮箱及 Tunnel 路由后才能异地访问，现有小程序入口保持不变。

### 任务管理

后台左侧统一进入“任务管理”，在“清单导入”和“任务看板”两个页签间切换。
切换时保留本页已选文件及查询内容，并刷新任务数据。

#### 清单导入
- 选择 Excel 文件（必须包含：机房名称、机房所在片区、设备类别、网元名称、设备型号、资产标签号、设备机架、生命周期状态、地点编码）
- 下载模板后删除示例行；允许在这 9 列之外增加其他业务列，系统会保留可识别的扩展字段
- 下载模板、选择 Excel 文件、预检清单
- 点击“导入并生成待盘点机房”
- 同一地点编码再次导入时，未领取的旧任务自动作废；已领取但未完成的旧任务停止录入，提示现场释放后领取最新任务。在旧任务释放前，新任务暂不可领取或派发。
- 早期任务没有地点编码时，仅按完全相同的机房名称识别旧版本；“传输1”和“传输2”等不同名称不会合并。
- 清单中名称唯一且字段未变化的设备，沿用旧任务最新有效盘点结果（含管理员修正）；新增、变化或同名多条的设备重新盘点。已登记 ODF／IODF 和盘盈一并沿用，保留原采集时间。原盘盈进入新清单时，按清单重新盘点。
- 连续导入多版只开放最新任务；已经完成的任务保留为历史，新轮次不自动沿用其采集结果。

#### 任务看板
- 查看所有任务进度
- 查看任务统计图、任务进度和超时任务
- 支持查询并作废任务
- 每次清单导入形成独立批次，任务可按导入批次查询；机柜记录只属于本轮任务。

### 资产盘点数据
- 查询并选择任务
- 汇总展示：设备总数、已盘、未盘、进度
- 查看设备盘点数据和现场机柜明细
- 可导出任务清单、设备盘点数据和现场机柜明细
- 完成任务的录入错误通过“修正现场反馈”新增管理员修正版本，原始反馈保留。
- 整个任务经现场确认完成后，管理员可点击“转整改”，填写问题、依据和要求，建立待审核单；在整改台账确认处理责任后再下发、处理和验收。建单需满足三方资料校验，同组已有未闭环单时不可重复创建。

### 三方比对

1. 管理员上传最新资产信息表，选择资产条码列；三方比对另需“资源名称、地点编码、规格型号”表头。条码必须唯一。
2. 选择同一批次的已完成机房。历史任务缺少地点编码时，在“地点编码与综资更新”中补录；不混用其他批次现场数据。
3. 先按任务设备记录核对综资与现场条码，条码不同时也在同一行显示；再按现场实扫条码与资产信息表核对，逐组展示综资、现场、资产三方原值。现场名称和地点继承其所属清单记录，不按实扫条码倒推名称。第一步发现问题时仍可查看第二步，最终三方一致条件不变。
   已有现场反馈但勾选无资产条码时，按其所属设备记录在同组展示参考原值，标注“现场无条码 / 待补录关联”，不拆成两组，不视为没有盘点，也不会自动填入综资条码。补齐真实条码前不能认定三方一致。
4. 单条码的型号由管理员选择“待判断 / 一致 / 不一致 / 无法确认”；多条码三方对照值和名称、地点、型号结论全部人工填写。填写判断依据后保存。
5. 只有待判断的条目先补判断；确认实际问题后建单。同一批次同一资产的多个问题合并一单；也支持从盘点数据页人工确认严重问题建单。
6. 综资改错先在原系统修改，再从“更新综资基线”上传所选机房的完整清单；保留本轮现场结果、原清单和历次基线。资产改错使用新资产信息表。
7. 型号相关内容变更后原判断失效（改回旧型号也需重判）；无关资产更新不会清空本设备判断。旧判断保留历史。
8. 可导出“综资与现场”“三方结果”两张工作表；AI 设置、模型检测和辅助分析保留。AI 读取同一三方范围的脱敏数据和已保存判断，不能代替人工判型号、派单或验收。

### 整改闭环台账

- 页签分为“三方问题待确认、整改工单、历史工单”，沿用统一后台查询栏、表格和弹窗样式。
- 管理员审核时确认现场、管理员或双方处理责任。只有现场责任才选择同片区人员派单；资产和综资由管理员在原系统修改并上传，不向现场派单。
- 现场只处理本整改单涉及的设备，可填写实际整改说明、更新条码/型号等反馈；若本单没有现场设备记录，可补录本设备。整个已完成机房仍保持锁定。
- 双方责任工单必须分别提交处理结果才进入待验收；仅写处理说明或上传新文件不会直接闭环。
- 管理员验收时，后端重新读取最新三方数据和有效人工判断。缺失、重复、缺码、名称或地点差异、型号待判断或不一致都会阻止闭环。
- 验收不通过可退回选定责任方继续整改；不要求整间机房重盘。误扫条码更正后按原设备记录追溯整改对象。
- 保留建单快照、验收快照、来源版本及每次处理人的说明和时间；关联未闭环工单的任务不能直接作废。
- 旧版工单在“历史工单”保留原记录，不算作已通过新三方规则的闭环；未完成问题请重新核实后建单。

### 设备机柜与 ODF / IODF 机架
- 小程序任务页分为“设备盘点”和“机架盘点”。传输综合柜随设备采集；ODF / IODF 单独登记，往期结果仅作参考。
- 设备型号可选择建议或直接手动填写，型号库仅辅助输入；确实没有型号的设备可选择“不涉及”。清单设备和盘盈登记口径一致，管理员后续可在后台更正，三方型号仍由管理员判断。
- 多台设备共用同一柜位和柜条码属于正常情况。同柜条码多柜位、同柜位多条码或跨设备/机柜/机架复用条码时，保存后展示冲突双方。机架同条码但类型或编号不同会拒绝登记，保留表单供核实。
- 全部清单设备处理后，点击“确认完成本次盘点”，须在弹窗确认机架已经完成盘点才提交；选择“继续盘点”返回机架页。完成后小程序只读。
- 管理员在“资产盘点数据”中按本次任务补录、更正或作废机架；盘盈设备可更正名称、作废误报。最新保存值覆盖当前展示和导出，作废记录退出当前汇总与核对，审计记录保留。
- “三方比对”的设备页下方独立核对传输综合柜，导出同时包含“传输综合柜核对”工作表。综资柜位从设备行“设备机架”汇总，现场柜条码使用有效设备反馈，再与同地点资产柜记录核对。
- 综资没有提供机柜条码，因此仅核对综资/现场柜位与现场/资产柜条码；不会将该结果标为三方柜条码一致。资产资源名称的“设备机架-”是柜类型前缀，核对柜位时与现场编号对应；设备规格型号含“机架/机柜”不会因此被改判为独立机柜或 ODF/IODF。

## API 接口

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | /api/upload_rooms | 上传Excel，按机房创建本批次任务 |
| GET | /api/workers | 查询所有现场人员 |
| GET | /api/tasks | 查询任务列表 |
| GET | /api/tasks/{id}/items | 查询任务下的设备清单 |
| POST | /api/scan | 提交盘点结果 |
| POST | /api/cabinets | 现场单独登记 ODF / IODF |
| POST / PUT | /api/admin/tasks/{id}/racks[/{rack_id}] | 管理员补录或更正本任务机架 |
| DELETE | /api/admin/tasks/{id}/racks/{rack_id} | 管理员作废误录机架，须填写原因 |
| DELETE | /api/admin/records/{id} | 管理员作废误报盘盈设备，须填写原因 |
| GET | /api/report/{id} | 获取盘点报告 |
| GET | /api/export/{id} | 导出结果Excel |
| POST | /api/login | 小程序登录 |
| GET | /health | 健康检查 |

## 微信小程序

代码在 `miniprogram/` 目录下，使用微信开发者工具打开即可。

### 小程序页面

- **登录页**：微信一键登录，开发模式可选测试账号
- **任务列表页**：展示本人任务、进度条、支持下拉刷新
- **设备盘点页**（核心）：逐设备扫码（资产条码+机柜条码）、勾选型号、填写备注、提交

### 开发配置

1. 打开微信开发者工具，导入 `equipment_inventory/miniprogram` 目录
2. 在 `env.js` 中修改开发环境的 `devApiBase`；线上调测使用本机后端地址，线下测试使用公网 HTTPS 地址
3. 模拟器中点击"微信一键登录"或选择测试账号
4. 开发测试阶段，后端代码用 `POST /api/login` 传入 `worker_001` / `worker_002` 模拟登录

### 小程序姓名和手机号同步

- 现场人员登录后，可在小程序首页填写真实姓名，并点击“授权手机号并同步”。
- 姓名由现场人员手工填写；手机号通过微信 `getPhoneNumber` 授权后，由后端调用微信接口换取并写入账号资料。
- 后端需配置 `WECHAT_APPID` 和 `WECHAT_SECRET`，可写入项目根目录 `.env`，`scripts/windows/start_backend.bat` 会自动读取。
