# 固定二维码资产模块

这个模块只把随机 `token` 编码到二维码中，不把当前传输设备名称写入二维码。因此资产从 A 设备改绑到 B 设备后，二维码图片和二维码地址都不变，扫码页面读取数据库中的最新状态。

## 配置

下载二维码前必须设置固定的扫码地址前缀：

```env
INVENTORY_PUBLIC_BASE_URL=https://inventory.example.com
```

未配置时，系统会拒绝下载二维码，避免把临时地址写进图片。二维码投入使用后不要修改该地址；更换服务器时应通过域名解析或反向代理保持这个地址继续可用。

安装依赖：

```powershell
pip install -r requirements.txt
```

## 管理接口

接口需要现有管理员 Bearer Token。

```text
POST  /api/qr-assets
GET   /api/qr-assets?query=...
GET   /api/qr-assets/import-template
POST  /api/qr-assets/import
GET   /api/qr-assets/{id}
PATCH /api/qr-assets/{id}
DELETE /api/qr-assets/{id}
POST  /api/qr-assets/{id}/binding
POST  /api/qr-assets/{id}/history
PATCH /api/qr-assets/{id}/history/{history_id}
DELETE /api/qr-assets/{id}/history/{history_id}
GET   /api/qr-assets/{id}/qrcode
```

PC 后台“二维码资产”页面支持下载模板和批量导入。模板每行是一组资产，包含：

- 资产条码
- 条码型号
- 条码所在机房
- 当前绑定传输设备名称
- 资产条码历史关联设备记录

历史关联设备使用中文分号分隔，并按从旧到新的顺序填写：

```text
PTN-00；PTN-01
```

批量导入采用单次事务：文件内条码重复、必填项缺失或条码已存在时整批不写入，修正 Excel 后重新导入即可。每一行会生成不同的固定 `token`。

创建示例：

```json
{
  "asset_barcode": "ASSET-001",
  "barcode_model": "资产标签",
  "room_name": "核心机房A",
  "current_device_name": "PTN-01",
  "current_device_ref": "NE-001"
}
```

改绑示例：

```json
{
  "device_name": "PTN-02",
  "device_ref": "NE-002",
  "change_reason": "设备替换"
}
```

改绑时会在同一事务中结束旧关联、写入新关联、更新当前设备。旧记录不会被覆盖或删除。

编辑资产时可以一次修改资产条码、条码型号、机房和当前设备。当前设备发生变化时，旧设备自动进入历史；固定 `token` 不变。

PC 后台支持资产组的新增、查询、编辑和删除，也支持已结束历史记录的新增、编辑和删除。删除资产组采用业务停用：扫码将不再显示该资产，但原固定编码永久保留且不会分配给其他资产。当前生效的设备关联只能通过资产编辑或“改绑设备”修改，不能在历史列表直接删除。

## 扫码接口

二维码页面：

```text
GET /qr/{token}
```

小程序或其他系统也可以直接使用 JSON 接口：

```text
GET /api/public/qr/{token}
```

返回当前资产条码、条码型号、机房、当前传输设备和历史关联设备。

扫码 HTML 和 JSON 响应均设置为不缓存，每次扫码都会读取数据库最新内容。

## 嵌入其他系统

集成时保留以下三个字段即可：

- `qr_assets.token`：二维码稳定标识
- `qr_assets.current_device_name/current_device_ref`：当前设备
- `qr_asset_bindings`：历史关联

如果目标系统已有资产、机房和传输设备表，可把 `current_device_ref` 和 `device_ref` 映射到其主键，先不改变本模块的接口结构。
