# 现场测试与开发调测操作指引

更新日期：2026-11-11。当前日常操作以 Mac 脚本为主；原文档中的 Windows `dev/trial` 切换方式已过时，不再作为当前操作步骤。功能操作见[系统操作手册](系统使用文档.md)。

## 1. 先区分两种模式

| Mac 弹窗名称／参数 | 用途 | 身份及连接 | 对异地后台的影响 |
|---|---|---|---|
| 线上调测／`online` | 本机开发者工具调试 | 测试人员账号、本机接口，脚本停止公网隧道 | 共享隧道停止，异地后台也受影响 |
| 线下测试／`field` | 现场手机真机测试 | 真实微信登录、公网 HTTPS，脚本启用隧道 | 主机、后端及连接正常时可用 |

“线下测试”不是离线模式。手机请求需要网络、后端和公网连接；本地草稿也不是完整离线同步能力。上表描述脚本切换目标，实际运行状态以配置、自检和真机验证为准，不以当前打开的开发者工具页面判断模式。

## 2. 启动与检查

1. 在运行系统的 Mac 上进入项目目录 `scripts/mac/`。
2. 双击 `start_all_mac.command` 启动本机服务，按终端提示保留窗口。此脚本不负责创建域名策略或启动已经停止的系统隧道。
3. 需要改变测试方式时，再使用 `switch_mode_mac.command`。不要在现场正常盘点时随意切换。
4. 检查本机后台和后端，再检查现场公网入口，最后用相应账号真机验证。

| 检查对象 | 地址／方式 | 说明 |
|---|---|---|
| 本机后台 | `http://127.0.0.1:5173` | 本机浏览器打开 |
| 后端健康 | `http://127.0.0.1:8000/health` | 预期 JSON 包含 `status: ok` |
| 现场公网接口 | `https://api.equip-inventory.xyz/health` | 本机正常不代表公网正常 |
| 异地后台 | `https://admin.equip-inventory.xyz` | 邮箱验证后还需后台账号登录 |
| AI Agent（可选） | `http://127.0.0.1:9000/health` | 不可用不影响普通盘点和规则比对 |

双击 `prepare_remote_admin_mac.command` 可构建异地后台页面并自检；`--check-only` 只检查已有页面和本机准备情况，不代表已验证公网可访问。

## 3. 切换模式

双击 `scripts/mac/switch_mode_mac.command`，选择需要的模式。也可从项目根目录终端执行其中一条：

```bash
./scripts/mac/switch_mode_mac.command online
```

```bash
./scripts/mac/switch_mode_mac.command field
```

脚本同步配置、重启后端、启停隧道并检查接口；系统授权框需要的是 Mac 管理员密码。失败时按终端说明核实是否已恢复，不要反复切换掩盖故障。

切换完成后：

1. 微信开发者工具重新编译。
2. 退出原小程序账号，用当前模式对应身份重新登录。
3. 手机体验版需要重新上传；脚本不会自动发布。
4. 真机测试还需在微信平台加入体验成员，并确认合法域名等发布配置。

不需要换模式时不要为了改邮箱、刷新后台页面或排查单次超时而运行切换脚本。邮箱维护按[开通指引](协作管理员后台访问开通指引.md)操作。

## 4. 一次现场验证流程

使用约定的测试机房与测试资料，不随意在真实已完成任务中试删、试改。

1. 完整管理员导入并预检清单，确认片区、机房及地点编码正确。
2. 现场人员领取本人片区任务，用部分资产条码搜索设备。
3. 采集型号、设备条码、机柜位、机柜条码；检查“无条码”“不涉及”等例外。
4. 在盘点中验证盘盈的修正和删除，验证 ODF／IODF 手工登记及误录删除。
5. 清单全部处理后，确认机架和清单外设备已盘完，再确认完成。
6. 在本人“已完成盘点”查看只读结果；管理员后台查看汇总和当前有效值。
7. 从三方比对查询并勾选已完成机房，核对资产按地点取数、型号人工判断及 Excel 输出。
8. 如需验证拼销或整改，使用专用样例并记录操作依据，分别验证撤销及验收条件。

验收记录区分“功能能操作”和“节省多少时间”。前后用时、人力、抽检结果按同口径记录，不能仅凭功能上线推定提效比例。

## 5. 连不上时按顺序排查

| 现象 | 先检查 |
|---|---|
| 本机网页打不开 | 管理页面进程及地址，后端健康接口 |
| 本机 API 也不通 | 后端进程、启动终端及日志，避免重复启动占端口 |
| 本机正常、公网不通 | Mac 网络、隧道服务、公网域名解析及路由 |
| 小程序提示 530／请求超时 | 记录时间、请求地址和操作，分段检查；不能仅凭错误码认定热点或密码问题 |
| 只有异地后台不通 | Access 邮箱、后台名单、专用域名及后台账号，勿用小程序域名绕过验证 |
| 只有 AI 不可用 | Agent 与模型配置，先继续不依赖 AI 的主业务 |

必要时使用 `scripts/mac/repair_tunnel_mac.command`，它会重启或调整连接，须避开正在提交盘点的时段。完整脚本说明见[脚本使用说明](../SCRIPT_GUIDE.md)。

## 6. 运行保障与资料安全

当前为本机承载服务，关机、休眠、断网、停止后端或隧道都会影响使用。现场测试期间保持主机和网络可用；后续按单位要求部署常开环境、备份恢复及运行监测。

现场链路为 HTTPS 与 Cloudflare Tunnel，并非单位内网专线。异地后台还有 Access 验证及后台角色权限，小程序使用微信身份与任务归属校验。不要在报错截图或对外材料中暴露密钥、验证码、手机号或真实业务资料。`.env` 和数据库不对外发送。

Windows 脚本仅作备用／历史资料，特别是旧 `switch_miniprogram_mode` 已不兼容当前结构，不照搬旧步骤。迁回 Windows 前按[脚本使用说明](../SCRIPT_GUIDE.md)单独验证，不在当前现场服务上试切。
