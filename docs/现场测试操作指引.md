# 现场测试与线上开发调测操作指引

适用场景：机房资产盘点系统在本机开发调测、现场体验版测试、以及现场测试结束后切回开发调测之间切换。

这份文档已经合并原《现场测试操作指引》，按步骤执行即可，不需要手工改代码。

## 1. 系统组成与常用地址

| 模块 | 启动脚本 | 默认地址 | 用途 |
|---|---|---|---|
| 后端 API | `start_backend.bat` 或 `start_backend_tunnel.ps1` | `http://127.0.0.1:8000` | PC 后台、小程序、AI 分析接口 |
| PC 后台 | `start_admin_vue.bat` | `http://127.0.0.1:5173` | 管理员导入清单、查看任务、导出数据、账号管理 |
| 本地 AI Agent | `start_local_agent.bat` 或 `start_local_agent.ps1` | `http://127.0.0.1:9000` | AI 分析和 Agent 对话 |
| 小程序 | 微信开发者工具打开 `miniprogram/` | 开发版/体验版 | 现场人员登录、领任务、扫码盘点 |
| 公网 API | Cloudflare Tunnel | `https://api.equip-inventory.xyz` | 体验版小程序访问本机后端 |

健康检查地址：

```text
http://127.0.0.1:8000/health
http://127.0.0.1:9000/health
https://api.equip-inventory.xyz/health
```

正常返回：

```json
{"status":"ok"}
```

## 2. 两种运行模式

### 2.1 开发调测模式：dev

适合在本机和微信开发者工具里调试。

- 小程序显示测试账号。
- 后端允许 `worker_001`、`worker_002`、`worker_005` 等测试用户登录。
- 小程序开发版走 `miniprogram/env.js` 里的 `devApiBase`，当前为：

```text
http://localhost:8000/api
```

### 2.2 现场测试模式：trial

适合现场人员使用微信体验版真实登录。

- 小程序隐藏测试账号。
- 后端关闭测试账号登录，走真实微信登录流程。
- 需要配置或输入 `WECHAT_SECRET`。
- 体验版小程序走 `miniprogram/env.js` 里的 `prodApiBase`，当前为：

```text
https://api.equip-inventory.xyz/api
```

## 3. 如何启动

### 3.1 启动开发调测环境

在项目根目录执行：

```powershell
.\switch_miniprogram_mode.bat
```

选择：

```text
1
```

然后按需启动服务。

只调 PC 后台和小程序主流程：

```powershell
.\start_backend.bat
.\start_admin_vue.bat
```

需要 AI 分析时，先启动本地 Agent：

```powershell
.\start_local_agent.bat
.\start_backend.bat
.\start_admin_vue.bat
```

启动后检查：

```powershell
Invoke-RestMethod http://127.0.0.1:8000/health
Invoke-RestMethod http://127.0.0.1:9000/health
```

打开 PC 后台：

```text
http://127.0.0.1:5173
```

微信开发者工具中打开 `miniprogram/`，重新编译后使用测试账号登录。

### 3.2 启动现场测试环境

在项目根目录执行：

```powershell
.\switch_miniprogram_mode.bat
```

选择：

```text
2
```

启动现场测试后端：

```powershell
.\start_backend_tunnel.ps1
```

脚本会读取 `.env`，并提示输入 `WECHAT_SECRET`。启动后确认本机 API 正常：

```powershell
Invoke-RestMethod http://127.0.0.1:8000/health
```

确认 Cloudflare Tunnel 常驻：

```powershell
Get-Service Cloudflared
Get-Process cloudflared
```

期望服务状态：

```text
Status: Running
StartType: Automatic
```

再确认公网 API 正常：

```powershell
Invoke-RestMethod https://api.equip-inventory.xyz/health
```

如需 PC 后台，在本机另开窗口启动：

```powershell
.\start_admin_vue.bat
```

现场测试时还需要在微信开发者工具中重新上传体验版。重点确认：

- 已切到 `trial`。
- 体验版使用真实微信登录。
- `prodApiBase` 指向 `https://api.equip-inventory.xyz/api`。
- 微信公众平台已把现场人员加入体验成员。

## 4. 如何关闭

### 4.1 正常关闭

哪个窗口启动的服务，就在哪个窗口按：

```text
Ctrl + C
```

如果提示是否终止批处理，输入：

```text
Y
```

常见窗口：

- 后端窗口：`start_backend.bat` 或 `start_backend_tunnel.ps1`
- PC 后台窗口：`start_admin_vue.bat`
- 本地 Agent 窗口：`start_local_agent.bat` 或 `start_local_agent.ps1`

### 4.2 按端口强制关闭

如果窗口找不到，先查看端口：

```powershell
Get-NetTCPConnection -LocalPort 8000,5173,9000 -State Listen
```

按进程 ID 关闭：

```powershell
Stop-Process -Id 进程ID -Force
```

一次性关闭三个本机服务：

```powershell
Get-NetTCPConnection -LocalPort 8000,5173,9000 -State Listen -ErrorAction SilentlyContinue |
ForEach-Object { Stop-Process -Id $_.OwningProcess -Force }
```

端口对应关系：

```text
8000  后端 FastAPI
5173  PC 后台 Vue
9000  本地 AI Agent
```

### 4.3 是否关闭 Cloudflare Tunnel

现场测试结束后，通常只需要关闭后端即可，`cloudflared` 可以继续作为系统服务常驻。

如果明确要停止公网入口：

```powershell
Stop-Service Cloudflared
```

再次启用：

```powershell
Start-Service Cloudflared
```

## 5. 从现场测试切回开发调测

现场测试场景通常是 `trial + start_backend_tunnel.ps1 + 体验版小程序 + 公网 API`。

切回开发调测时，按下面顺序做：

```text
1. 关闭现场测试后端窗口
2. 如不再需要 AI，关闭本地 Agent 窗口
3. 运行 switch_miniprogram_mode.bat
4. 选择 1，切回 dev
5. 重新启动 start_backend.bat
6. 重新启动 start_admin_vue.bat
7. 微信开发者工具重新编译 miniprogram/
8. 使用测试账号登录验证
```

对应命令：

```powershell
.\switch_miniprogram_mode.bat
.\start_backend.bat
.\start_admin_vue.bat
```

验证点：

- `miniprogram/pages/login/login.js` 中开发登录开关应为 `true`。
- `start_backend.bat` 中 `INVENTORY_DEV_LOGIN` 应为 `1`。
- 小程序开发版走 `http://localhost:8000/api`。
- 登录页能看到测试账号。
- `http://127.0.0.1:8000/health` 返回 `{"status":"ok"}`。

注意：如果你想继续用公网地址给外部人员联调，就不要切回 `dev`。保持 `trial`，继续使用 Tunnel 和体验版。

## 6. 现场测试前最小检查清单

```text
1. switch_miniprogram_mode.bat 选择 2
2. start_backend_tunnel.ps1 启动后端并输入 AppSecret
3. Get-Service Cloudflared 确认 Running
4. 访问 https://api.equip-inventory.xyz/health
5. 重新上传微信体验版
6. 用现场微信账号登录测试
7. PC 后台本机打开 http://127.0.0.1:5173 查看任务和账号
```

## 7. 常见问题

### 7.1 登录失败

优先检查：

- `WECHAT_APPID` 是否配置。
- `WECHAT_SECRET` 是否输入或写入 `.env`。
- 当前是否真的切到了 `trial`。
- 微信体验版是否重新上传。
- 体验成员是否已加入。
- PC 后台是否已启用对应现场人员账号。

### 7.2 小程序提示网络错误

优先检查：

- `https://api.equip-inventory.xyz/health` 是否可访问。
- `cloudflared` 服务是否 Running。
- 本机后端是否还在监听 `127.0.0.1:8000`。
- 微信公众平台 request 合法域名是否包含 `https://api.equip-inventory.xyz`。

### 7.3 PC 后台打不开

优先检查：

- `start_admin_vue.bat` 是否启动。
- `127.0.0.1:5173` 是否被占用。
- 后端 `8000` 是否正常。
- PC 后台只建议本机访问，不要把 `127.0.0.1:5173` 发给别的电脑。

### 7.4 AI 分析不可用

这通常不影响盘点主流程。

优先检查：

- 本地 `9000` Agent 是否启动。
- `DEEPSEEK_API_KEY` 是否配置。
- `INVENTORY_AI_AGENT_URL` 是否可达。
- PC 后台 AI 页面是否已点击“检测可用”。

## 8. 一句记忆版

现场测试：

```text
切 trial -> 启现场后端 -> 看 Tunnel -> 上传体验版 -> 现场账号登录
```

```text
关现场后端 -> 切 dev -> 启本机后端 -> 启 PC 后台 -> 开发者工具重新编译
```

## start_local_agent、enable_local_agent以及configure_ai_env，这三个脚本使用场景是什么？

这三个脚本是分工的，不是每次都全跑一遍。
configure_ai_env
场景：第一次接入 AI，或者要改 DeepSeek 的 API Key / 模型名 / Base URL。
作用：写入项目根目录 .env，配置 DEEPSEEK_API_KEY、DEEPSEEK_MODEL、DEEPSEEK_BASE_URL，顺带补一些后端基础环境。
适合：你要让本地 agent 真正能去调用 DeepSeek。

enable_local_agent
场景：你已经准备好本地 agent，希望后端改走本地 agent，而不是直接在后端里调模型。
作用：把 INVENTORY_AI_AGENT_URL=http://127.0.0.1:9000/analyze 写进 .env，并生成 INVENTORY_AGENT_TOKEN。
适合：切换 AI 分析路由，让后端通过本地 agent 统一调度。

start_local_agent
场景：你要真正把本地 agent 服务跑起来。
作用：启动 local_agent.app，监听 127.0.0.1:9000。
适合：后端已经配置好路由后，启动这个服务让 AI 分析可用。

典型顺序是：
configure_ai_env -> enable_local_agent -> start_local_agent -> 重启后端。
一句话记：
configure_ai_env 负责“AI 账号和模型配置”
enable_local_agent 负责“后端改走本地 agent”
start_local_agent 负责“把 agent 服务启动起来”
