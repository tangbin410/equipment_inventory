# 代码检查与精简记录

检查日期：2026-11-13。范围包括后台、后端、小程序及部署入口；重点为采集保护、机房范围、三方比对、盘亏盘盈拼销、机房建模和查询导出。此次检查采用代码阅读、临时数据库回归及隔离浏览器验证，不读取真实 `.env`，不对真实业务记录执行测试写入。

## 已修复的问题

| 问题 | 修正后的行为 |
|---|---|
| 盘点中现场可删除管理员补录或修正过的 ODF／IODF | 服务端拒绝删除，小程序隐藏删除按钮；管理员仍可在后台按原因作废 |
| 作废任务只校验部分新版整改单，旧版或规则工单可能漏检 | 复用统一关联工单校验；未闭环工单均阻止作废，其他机房及已闭环／驳回工单不误拦截 |
| 一个设备管理多个机柜时，把整段柜位当成单一柜位，产生条码冲突误报 | 拆分柜位，仅在单柜位明确时建立对应关系；未对应的多条码与多柜位不推断配对，跨实体复用条码仍校验 |
| 整改候选快速切换批次时，慢旧请求可能覆盖新批次 | 切换时清空旧候选，仅接收当前请求结果；刷新、失败或离开页面不能恢复旧候选 |
| 资产表读表头期间换文件，可能显示旧文件表头并提交新文件 | 预览绑定原文件，忽略过期预览；导入期间锁定文件和条码列，防止重复导入 |
| 连点资产条码或关闭弹窗后，旧请求可能覆盖新结果或重新打开弹窗 | 仅保留最后一次查询，关闭及离开页面使旧请求失效，旧条码队列停止继续查询 |

## 精简与加载调整

- 任务作废与清单更新共用未闭环工单保护，删除重复且口径不完整的校验代码。
- 后台页面改为按需加载，机房建模等模块首次使用时再加载。相同环境构建时，入口 JavaScript 从约 1.31 MB 降至 1.06 MB；这是入口文件大小变化，不代表总体下载量或业务耗时同比降低。公共 UI 依赖仍较大，构建保留体积提示。
- 增加后台 `npm test` 入口；保留业务兼容字段和必要审计记录，没有为减少行数拆散业务逻辑或删除历史数据。

## 本轮重新下发任务的数据口径

已完成 A 机房再次下发时，旧任务及原始反馈保留，新任务重新采集，不自动沿用上轮已完成结果。新任务完成后，三方比对和建模默认使用最近一次已完成结果；旧轮次仍可在盘点数据中查询。只有替换尚未完成任务并释放旧任务时，才按规则沿用未变化设备、手工机架及盘盈。

## 现有边界与后续优先项

1. ODF／IODF 目前主要核对现场和资产，综资机架基线待补；不能称作完整的机架三方自动比对。
2. 本系统保存综资修正及人工结论，不自动回写外部综资／资产生产系统；拼销后的跨机房调拨仍需办理。
3. 设备实际 U 位没有采集，建模柜内布局仅示意。多柜位与柜条码的逐柜关系可在后续采集中补充。
4. 后续应结合实际机房数量开展容量和并发验证，完善常开部署与备份恢复演练。本次未重建已有 Docker 镜像，交付新版时需按 Docker 文档重新构建验收。

Git 同步范围为开发源码、测试、文档与干净部署模板；真实 `.env`、数据库、备份、运行导出、依赖目录、Docker 运行包和镜像文件均不纳入代码提交。
