# 协作管理员后台访问开通指引

更新：2026-11-02。适用于让其他同事从不同地点，通过互联网访问当前资产盘点后台。本文是操作指引，不代表已经为示例中的新人员开通账号或邮箱。

后台入口：[https://admin.equip-inventory.xyz](https://admin.equip-inventory.xyz)。

开通一名同事需要完成三件事：**创建独立后台账号、在 Cloudflare 放行其邮箱、在本机 `.env` 放行同一邮箱并重启后端**。仅新建账号或只改一处邮箱，都不能完成异地开通。

放行名单以 Cloudflare 与本机 `.env` 两处实际配置为准；`owner@example.com` 仅代表主管理员邮箱示例。下面以同事 B、登录编码 `admin_b`、邮箱 `b@example.com` 举例，请全部替换成真实信息。

## 一、先准备哪些信息

| 信息 | 谁提供 / 填写 | 用途 |
|---|---|---|
| B 的姓名 | B 提供 | 后台显示操作人 |
| B 自己能收信的完整邮箱 | B 提供 | 接收 Cloudflare 登录验证码 |
| 独立登录编码，例如 `admin_b` | 你分配 | 后台账号登录；不要与其他账号重复 |
| 独立密码 | 在后台设置，12—128 位 | 后台第二层登录，不是邮箱密码 |
| 角色 | 你选择“协作管理员” | 使用既定协作权限 |

B 不需要注册 Cloudflare 账号，也不需要登录你的 Cloudflare 控制台。不要把你的邮箱、验证码或主管理员账号交给 B 共用；后台密码直接在账号表单中设置，不用发送给 AI。双方通过你们认可的私下方式交付账号和初始密码。

## 二、你操作：创建独立后台账号

1. 用你自己的**完整管理员**账号登录后台。
2. 进入左侧“账号管理”，点击“新建空白账号”。
3. 填写“登录编码”和“姓名”，角色选“协作管理员”。
4. 填写并再次确认 12—128 位独立密码。
5. 按表单选择登记片区，按需填写手机号，勾选“启用账号”，点击“保存”。管理员的登记片区不会限制后台可见范围。

如果已经为 B 建好了独立协作账号，直接核对登录编码、角色和启用状态即可，不必重复创建。需要换密码时，由完整管理员在该账号行点击“重置密码”；重置会使此账号原有后台登录失效。

如果看不到“账号管理”，先检查当前登录角色。协作管理员无法创建账号，需要换用完整管理员。

## 三、你操作：在 Cloudflare 添加 B 的邮箱

1. 用你自己的 Cloudflare 管理账号打开 [Cloudflare 控制台](https://dash.cloudflare.com/)。
2. 进入“Zero Trust → Access controls → Policies”。
3. 找到“仅允许指定管理员邮箱”这条策略，打开编辑。
4. 保持 Action 为 **Allow**。在 Include 中找到 **Emails**，添加 B 的完整邮箱，如 `b@example.com`，保留原有已授权邮箱。
5. 按页面按钮保存。回到“Applications → 资产盘点后台”，核对该应用仍绑定这条策略，保护域名仍是 `admin.equip-inventory.xyz`，Path 留空，登录方式为 One-time PIN。

添加的是指定完整邮箱，不是把 Everyone、Bypass 或“Login Methods: One-time PIN”单独设成 Include 来放行所有人。不要重建已存在的应用，不要改变原小程序 `api.equip-inventory.xyz` 的路由或添加邮箱验证。

## 四、你操作：在本机 `.env` 添加同一个邮箱

真实配置文件位于：

```text
/Users/tangbin/equipment_inventory/.env
```

文件名是 `.env`，不是 `.evn`。它是隐藏文件，可用以下任一种方式打开：

- 访达打开项目文件夹，按 `Command + Shift + .` 显示隐藏文件，再打开 `.env`。
- VS Code 中按 `Command + P`，输入 `.env`，选择项目根目录的这个文件。

搜索 `INVENTORY_ADMIN_ALLOWED_EMAILS`，在原有邮箱后用**英文逗号**添加 B 的邮箱。例如：

```dotenv
INVENTORY_ADMIN_ALLOWED_EMAILS=owner@example.com,b@example.com
```

保存文件。这个例子没有真的开通 `b@example.com`，实际操作应使用 B 在 Cloudflare 中填写的同一邮箱。不要填写邮箱密码，不要改其他密钥、域名、AUD 或模式开关，也不要用 `.env.example` 覆盖真实 `.env`。

## 五、你或维护人员操作：完整重启后端

修改 `.env` 后需要让实际运行的后端重新加载。**刷新网页、重新编译小程序、代码热重载，都不能替代完整重启后端。** 再次双击“一键启动”也可能只复用已有进程。

如果后端是从一个单独的终端窗口启动的：

1. 找到实际启动后端的那个终端，按 `Control + C` 停止它，等待命令提示符返回。
2. 在终端运行：

   ```bash
   cd /Users/tangbin/equipment_inventory
   ./scripts/mac/start_backend_mac.sh
   ```

3. 保留这个运行窗口，确认 [本机健康接口](http://127.0.0.1:8000/health) 返回 `{"status":"ok"}`，再进行下一节的真实登录验证。

如果后端由“一键启动”的终端启动，可以在**拥有该后端进程的那次一键启动窗口**按 `Control + C`，再双击 `scripts/mac/start_all_mac.command` 恢复本次被停止的服务。一键启动退出只停止它当次新启动的进程，复用的已有后端不会因此停止。

如果找不到实际启动窗口，或者不确定 8000 端口由哪个进程管理，先让维护人员识别该后端的启动来源，再受控停止并重启。下面只用于查看占用，不能据此批量关闭 Python 进程：

```bash
lsof -nP -iTCP:8000 -sTCP:LISTEN
```

**只更新邮箱不需要切换小程序模式或重启隧道。** `scripts/mac/prepare_remote_admin_mac.command --check-only` 可以检查本机准备情况，但它不会重启后端；该检查通过也不等于 B 已经能够登录。

## 六、B 操作：第一次登录

将下面这段交给 B 即可；不必把本机 `.env` 或 Cloudflare 控制台权限交给他。

1. 在电脑浏览器打开 [资产盘点后台](https://admin.equip-inventory.xyz)。不要使用 `127.0.0.1:5173`，那是运行系统的 Mac 上的本机地址。
2. 在 Cloudflare 验证页面填写**你自己的、已获准的邮箱**，点击“Send login code”。
3. 打开自己的邮箱，查看验证码邮件，必要时检查垃圾邮件。将验证码填回网页，点击“Verify”或“Sign in”。验证码有效期为 10 分钟，且只能使用一次；重新申请后旧验证码失效。[Cloudflare 官方验证码说明](https://developers.cloudflare.com/cloudflare-one/integrations/identity-providers/one-time-pin/)
4. 看到“管理员登录”后，输入分配给你的**登录编码和后台密码**。这里不填邮箱验证码或邮箱密码。
5. 登录后核对左下角显示的是自己的姓名和“协作管理员”，再打开任务、盘点数据或三方比对页面。

会话有效期间可能直接进入已登录页面，无需每次打开都重新收验证码。

## 七、B 可以做什么

| 可以 | 不可以 |
|---|---|
| 查看全部机房、任务、盘点数据和资产表 | 管理其他人的账号、角色和密码 |
| 执行三方比对、人工判断型号及人工比对 | 新建、导入、派发或删除/作废盘点任务 |
| 修正设备反馈、补录或更正机架 | 导入资产表、修改系统或 AI 配置 |
| 按现有原因和历史要求作废误录机架、误报盘盈 | 执行 AI 分析/聊天或整改审核、派发、验收 |
| 补地点编码、更新已有任务的综资基线、导出资料 | 维护二维码资料 |

权限由后端检查，不能仅凭某个按钮是否显示判断权限。协作账号能查看和导出全部机房资料，应分配给你认可的人员；系统不能阻止已获准人员自行保存或转发导出的资料。

目前 Cloudflare 邮箱和后台账号**尚未一对一绑定**。邮箱白名单控制谁可以进入，后台账号控制操作权限；因此应使用各自独立的账号，避免共享账号造成操作人混淆。

## 八、常见问题

| 现象 | 先检查什么 |
|---|---|
| 填了邮箱却没有验证码 | Cloudflare 是否保存了 B 的准确邮箱；是否查看垃圾邮件；重新申请后只用最新验证码。页面显示“已发邮件”不一定代表该邮箱被放行，Cloudflare 会对未获准邮箱显示相同提示以防枚举。[官方说明](https://developers.cloudflare.com/cloudflare-one/integrations/identity-providers/one-time-pin/) |
| 邮箱验证通过，但出现 403/无权访问 | 本机 `.env` 是否也加入同一邮箱，保存后是否完整重启后端；维护人员再检查 Access 配置。若只有某个操作出现 403，也可能是角色无权执行 |
| 后台提示账号或密码错误 | 使用登录编码和后台密码，核对账号是否启用；协作账号忘记密码由完整管理员重置；完整管理员也无法登录时使用下方本机恢复工具 |
| 登录成功，但没有“账号管理” | 协作管理员的正常权限，不是登录故障；账号维护使用完整管理员 |
| 出现 530、连接失败或超时 | 先检查运行系统的 Mac 是否开机联网、后端和隧道是否运行，再检查域名/路由状态；530 本身不能直接认定是手机热点原因 |
| 切模式后所有异地访问都失败 | Mac 的“线上调测 / online”会停止共享公网隧道，远程后台也会断开；“线下测试 / field”使用真实微信及公网隧道。只更改邮箱时不要为此切模式 |
| 别人在自己电脑打开 127.0.0.1 失败 | 使用公网后台域名；127.0.0.1 指向对方自己的电脑 |

当前系统运行在这台 Mac 上，它需要持续开机、保持网络和隧道运行。关机、休眠导致断网或停止共享隧道时，异地访问会受影响。

### 完整管理员忘记密码

在运行系统的 Mac 上打开 [本机密码恢复工具](../scripts/mac/reset_admin_password_mac.command)。输入登录编码（默认 `admin_001`），隐藏输入两次 12—128 位新密码，按提示确认后完成恢复。终端输入密码时不会显示字符；不要把新密码发给 AI。工具会先备份数据库，更新后使该账号旧登录失效并保留本机恢复审计，不修改角色、业务资料或 `.env`，也不需要重启服务。

恢复后返回后台使用登录编码和新密码登录。不要修改 `.env` 的初始化密码来尝试重置已有账号；邮箱验证码与后台密码是两层认证，目前邮箱还未与后台账号一对一绑定，不提供仅凭获准邮箱重置任意账号的功能。

## 九、不再允许 B 访问时

1. 用完整管理员进入“账号管理”，找到 B 的独立后台账号，点击“停用”。其旧后台会话随即失效；保留账号和操作历史，不必删除业务记录。
2. 从 Cloudflare“仅允许指定管理员邮箱”策略的 Emails 中移除 B 的邮箱，保存，保留其他仍需使用的邮箱。
3. 从本机 `.env` 的 `INVENTORY_ADMIN_ALLOWED_EMAILS` 中移除同一邮箱，保存并按第五节完整重启后端。
4. 让 B 的原会话再次访问，确认不能读取后台资料。仅删除 Cloudflare 策略中的邮箱时，不应假定其此前已发出的会话立刻全部失效；本机名单同步移除并加载后，原邮箱的 Access 身份也会被后端拒绝。

如果 B 仍需要现场小程序账号，先确认这里停用的是其独立后台账号，避免误停现场账号。

## 十、开通后逐项验收

下面是每次实际开通要填写的检查项，不表示本文已经完成了新人员验收。

- [ ] B 的后台账号独立、角色为协作管理员、状态启用。
- [ ] Cloudflare 和本机 `.env` 两处邮箱一致，原主管理员邮箱仍保留。
- [ ] 后端已完整重启并通过本机健康检查。
- [ ] B 从其他网络打开公网入口，完成自己的邮箱验证及后台账号登录。
- [ ] 页面显示 B 自己的姓名和协作管理员角色，任务与盘点数据能加载。
- [ ] 三方比对能加载；需要导出时，实际检查下载和内容。
- [ ] B 没有账号管理、任务删除和系统配置权限。
- [ ] 原小程序登录、盘点和提交不受本次开通影响。
