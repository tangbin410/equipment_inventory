# 当前系统功能清单与汇报口径

核对日期：2026-11-13。根据当前后台、小程序及后端代码整理；用于功能介绍和领导汇报，不代表所有功能均已完成生产验收。具体操作见[系统使用文档](系统使用文档.md)。

## 1. 系统定位

面向运营商传输维护场景，将“清单准备—任务领取—现场扫码—资料比对—问题处理—复核验收”集中到同一套系统。当前重点是提高数据采集效率、减少后台整理工作，并让问题及处理过程可追踪。

系统采用 PC 管理后台与微信小程序协同：管理员负责清单、资料修正和判断，现场人员负责扫码采集及指定整改反馈。规则比对是主要判断手段，AI 提供辅助分析和对话建议。

## 2. 已实现的主要功能

### 2.1 任务管理与采集准备

| 功能 | 当前行为 | 业务价值 |
|---|---|---|
| 按机房导入清单 | Excel 标准模板、预检、按片区及机房生成任务；保留设备类别、型号、资产标签号、设备机架、地点编码等字段 | 减少手工分发、统一采集口径 |
| 任务领取及分派 | 现场人员领取所属片区任务；后台也有单个和批量分派能力 | 明确盘点责任人 |
| 同机房清单更新 | 旧任务未领取时作废；已领取、未完成时提示先释放再领取新任务。此时业务字段未变的设备沿用已盘结果，变化或新增设备重新盘点；机架和清单外盘盈记录可承接。已完成旧任务保留历史，新一轮不自动沿用 | 减少重复扫码，避免同时执行新旧清单 |
| 任务看板 | 整体、片区和状态统计；列表支持查询、分页、连续序号与导出查询结果。未查询时不展示列表 | 便于任务较多后的查找和进度汇报 |
| 作废任务 | 管理员查询并填写原因后作废，保留审计信息 | 清理错误任务并保留处理依据 |

### 2.2 小程序现场盘点

| 功能 | 当前行为 | 业务价值 |
|---|---|---|
| 我的任务与已完成盘点 | 待盘、盘点中任务和本人完成任务分开；已完成任务只读 | 减少查找和误操作 |
| 设备类别提示 | 网元名称前显示导入的设备类别 | 方便现场识别和定位设备 |
| 搜索与筛选 | 支持名称、型号、条码、柜位等查询，其中条码支持包含式模糊查询 | 只有条码也能快速找到待盘设备 |
| 现场设备采集 | 记录型号、设备资产条码、机柜位、机柜条码及备注；型号可手输或选择“不涉及”，支持登记无条码 | 减少手抄并保留现场例外情况 |
| 盘亏登记 | 对清单内未找到设备记录未找到原因 | 将“没有找到”作为明确结果 |
| 盘盈登记 | 对清单外实物新增记录；盘点中可修正本次录入、删除错误盘盈 | 补齐清单外实物并纠正录入错误 |
| ODF/IODF 独立盘点 | 现场手工登记类型、机架编号（即资源名称）和资产条码；可删除误登记，往期记录供参考 | 将机架与设备所属传输综合柜分开 |
| 未盘优先 | 已处理设备下沉，未处理设备优先展示 | 减少重复翻找 |
| 人工确认完成 | 清单设备处理完毕后，提醒确认机架及清单外设备已盘点，现场确认后锁定任务 | 避免扫完清单即自动结束，防止漏录机架 |
| 完成后保护 | 已完成任务只读；管理员已修正的设备不再允许现场重新覆盖，机架不允许现场删除 | 稳定正式比对的数据来源 |

设备类别沿用清单字段，可用于省干设备、交换机、OTN、SPN、OLT、SDH、PTN 等设备的统一盘点。这里的“覆盖”指同一采集流程支持这些类别，不表示已对接对应网管协议、自动识别设备或自动读取配置。

### 2.3 盘点数据与资料维护

| 功能 | 当前行为 | 业务价值 |
|---|---|---|
| 查询并选择机房任务 | 按机房、领取人、片区等查询，在弹窗勾选数据范围 | 按需查看和导出 |
| 当前有效结果 | 展示设备类别、现场实物、综资基线及盘点结论，设备、综合柜、ODF/IODF 分表展示 | 集中查看现场与清单差异 |
| 修正现场反馈 | 管理员修正型号、设备条码、柜位、机柜条码等；页面、汇总和导出使用最新有效值 | 简单录入错误无需整间机房重新盘点 |
| 修改综资基线 | 已完成机房可修改本系统中的综资型号、条码及柜位；也有整机房基线更新入口 | 用修正后的资料继续比对 |
| 综合柜汇总 | 按设备盘点最新有效值（含管理员修正）汇总综合柜 | 使设备表和综合柜表保持一致 |
| Excel 导出 | 输出当前有效盘点数据；设备、综合柜、ODF/IODF 分别组织 | 减少重复整理，方便留档与线下处理 |

管理员修正“覆盖旧数据”指当前业务展示和输出采用最新值；系统仍保留必要的原始记录及操作依据。修改综资基线只更新本系统，不会自动写入外部综资生产系统。资产信息表通过导入更新，资产原系统的关联及调拨须通过其业务流程办理。

### 2.4 资产信息

- 上传 Excel 资产台账，识别表头并选择条码列；资产条码要求唯一、非空。
- 以最新资产快照供查询和比对，三方比对需要资源名称、地点编码、规格型号等列。
- 点击条码查看资产明细，可配置弹窗显示哪些字段；字段设置区支持折叠。
- 资源名称为空的资产单独列为“未关联资源条码”，交管理员核实，不能直接认定为盘盈或报废。

### 2.5 三方比对

| 范围或环节 | 当前规则 |
|---|---|
| 比对机房选择 | 只选择已人工确认完成的机房；查询弹窗按机房或领取人等条件筛选，每个机房默认展示最近一次已完成记录 |
| 资产取数范围 | 仅使用地点编码与所选综资机房一致的资产，不将整份资产表全部纳入本次比对 |
| 设备分组 | 在机房范围内按网元/资源名称关联；同一组集中展示综资、现场、资产三行，条码是核对字段 |
| 综资与现场 | 核对设备条码、机柜位；设备型号由管理员判断 |
| 综资与资产 | 核对资源名称、资产条码、地点编码；规格型号由管理员判断 |
| 现场与资产 | 核对资产条码、地点编码；现场地点编码沿用其所属综资任务资料 |
| 人工判断 | 两处型号分别判断，状态为待判断、一致、不一致、无法确认；同名多条、多条码等复杂情况人工核对，不自动任选记录 |
| 修改后再比对 | 使用最新有效反馈、综资基线和资产快照；资料变化后旧判断需重新核实 |
| 问题展示及导出 | 集中展示差异和处理入口；“导出设备比对”包含人工核对后的有效填写值及判断 |

两类资源需单独说明：

1. **传输综合柜**：综资目前只有设备行中的柜位；柜位可核对，机柜条码主要核对现场与资产。不能把未提供的综资机柜条码当成已取得的数据。
2. **ODF/IODF 机架**：当前主要核对现场登记与同地点资产信息，资源名称即机架编号，不比型号；资产独有机架也展示。综资机架基线仍待补齐，不能称为机架已经实现完整的三方自动比对。

“三方一致”是本系统在当前资料和人工判断基础上的结论，不等于三个外部生产系统已自动完成数据同步。

### 2.6 盘亏盘盈拼销

- 在盘亏、盘盈行用“拼销”替代“修改综资”。盘亏查盘盈，盘盈查盘亏，候选来自各机房最近一次有效的已完成盘点。
- 初次打开只推荐条码或网元/资源名称有匹配依据的最多 15 条；没有推荐则为空。管理员可输入条件后查询，结果分页显示。
- 管理员核实为同一实物后，填写依据并确认。同机房形成一条有效设备，跨机房归实际找到的机房，原机房保留迁出提示。
- 原始两条记录保留，支持撤销；来源数据变化后提示重新核实。
- 跨机房拼销仍标记待调拨，外部综资及资产的调拨另行办理；不能仅凭拼销就认定三方一致。

仅型号相同、机柜条码相同不足以证明是同一设备。详见[拼销使用说明](盘亏盘盈拼销使用说明.md)。

### 2.7 整改台账

现有代码具备“问题确认—建单—审核—处理—反馈—复核—验收/退回”的流程：

- 管理员确认比对问题后建单，避免未确认的 AI 建议直接下发。
- 审核时区分现场处理责任和管理员处理责任；涉及现场的指定现场人员，综资/资产资料由管理员处理。
- 小程序展示本人整改任务，填写处理说明，必要时提交本单设备的新反馈。
- 管理员提交资料处理结果，复核时读取最新三方比对；符合要求才验收，不通过可退回继续处理。
- 保存问题快照、责任人、处理记录和状态，避免同组问题重复建立未闭环工单。

可以汇报为“已具备整改工单和人工验收机制”。实际闭环仍依赖现场整改、外部原系统资料维护及管理员验收，不能表述成系统已自动完成原系统整改。当前业务重点仍是采集和比对，整改流程效果需通过试点案例验证。

### 2.8 账号、安全与辅助功能

| 功能 | 当前能力及边界 |
|---|---|
| 账号管理 | 完整管理员维护账号、片区、手机号、启停状态及管理员密码重置 |
| 协作管理员 | 查看全部机房、比对、导出、修正反馈、更新本系统综资基线及拼销；不能管理账号、删除任务或修改系统配置 |
| 现场权限 | 以账号、片区和任务领取关系限制操作；完成任务锁定 |
| 异地后台入口 | 可配合 Cloudflare Access 邮箱验证、后台独立账号密码及服务端权限控制使用；访问名单须按指引维护 |
| 操作留痕 | 重要资料修正、拼销、任务和工单操作保留审计或处理记录 |
| 二维码资产 | 独立维护二维码资产、当前设备绑定及历史记录，支持生成二维码与扫码查看；扫码公开页应按其适用范围管理信息 |
| AI 辅助分析 | 有模型状态检测、分析报告、历史报告及 Agent 对话能力；按规则准备上下文并处理敏感字段，输出供管理员复核 |

AI 功能依赖配置和模型可用性，当前报告严谨性仍需优化，不能作为自动验收依据。业务数据规则比对与人工判断可独立于 AI 分析使用。AI 辅助编写系统代码与系统内置 AI 分析是两个不同的成果口径。

## 3. 领导汇报时建议明确的三条边界

1. **能力已实现与成效已验证分开**：可以展示扫码采集、自动汇总、规则比对、人工拼销和工单闭环；节省多少人时、提高多少准确率须有同口径实测，不先填写估算百分比。
2. **本系统修正与原系统整改分开**：本系统保存最新有效值并输出结果；外部综资和资产的关联、调拨、重新贴标等仍需人工办理，再导入/更新资料核验。
3. **试运行与正式生产部署分开**：当前部署依赖个人电脑、电源与网络，关机或连接异常会影响现场；“线下测试模式”不等于无网离线采集。异地访问采用加密访问链路与访问控制，不能称为完全内网、不出公网或绝对不会泄露。

## 4. 建议纳入成果页的可核实指标

| 指标 | 建议计算口径 |
|---|---|
| 现场盘点耗时 | 同规模、相近复杂度机房的每百台盘点人时，区分行程与实际盘点时间 |
| 后台整理耗时 | 每个机房从收齐资料到形成可用比对 Excel 的人时 |
| 完成工作量 | 已完成机房、已处理设备、已登记机架，限定明确统计期间 |
| 问题发现与处理 | 已确认问题数量、人工拼销数量、已验收闭环数量；不能将待判断直接计为已发现错误 |
| 采集质量 | 必填字段完整率、重复登记率、抽检差错率，说明抽检样本 |

尚未实测的指标标为“待试点测量”。成果页可以先突出已经验证的流程变化：少手抄、少重复汇总、能追溯、能按机房核对、问题有处理入口。
